It would be overkill. A decision doc is for a choice that stays live: credible options traded against several criteria, where a future reader would want to re-run the judgment. Here the HLD tenets settle it. Both alternatives need runtime network access, which the no-network tenets forbid, so a cold reader has no reason to reopen the question. The choice affects only the registry node, and no other node is sized around it.

A single row in the registry LLD's Decisions & Alternatives table is enough. It would name the chosen SQLite index, the two rejected options, and the tenet that rejects them. If the tenets ever change to allow network lookups, that row is where someone would revisit the choice.
