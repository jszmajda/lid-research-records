**Rulings I need from you:**

1. **Can a fresh edit settle someone else's review item?** If a visit has competing revisions and a worker submits against the current revision, does that submission clear the competing revisions (visit becomes export-eligible) or do they persist until a coordinator resolves? *I propose: persist — a worker must not be able to settle a review item that involves another worker's edit.*
2. **May a coordinator select the current revision itself?** I say yes — that is how a coordinator rejects a competing edit while keeping the existing state (and the visit then exports cleanly).
3. **Two coordinators resolve the same visit at once.** *I propose: first accepted resolution wins; the second is rejected because the visit no longer has unresolved work.*
4. **A stale submission arrives after a visit was already resolved.** Mechanically this creates new review work and the visit becomes unresolved again. *I propose: yes, automatically — that is not the "reopening" case, which is a deliberate act and stays deferred.*
5. **A retry of an already-accepted submission.** *I propose: return the original acceptance result verbatim (revision ID, receipt time, and the unresolved flag as it stood at acceptance); the tablet calls Get visit for live state.*
