**Intent-narrowing edge audit — three forks need your ruling before tests land**

1. **Resolution selection set.** REC-012 currently lets a coordinator select *any retained revision*, which includes rewinding to an old ancestor of the head or picking a revision that already has pending descendants. Should the selectable set be only the current head and the pending branch tips? I recommend restricting it — it keeps resolution among the live alternatives and avoids silently rewinding later linear edits.
2. **Idempotency key scope.** REC-002/003 say an "accepted idempotency key" without saying unique per what. Per submitting author/device, per visit, or global? I recommend per author, so two tablets cannot collide and a retry is judged against the right submission.
3. **New visit on an archived plot.** REC-016 accepts any plot that resolves, and archived plots resolve, so a worker on a stale offline catalog could create a *new* visit for a plot archived since publication. Should record-store reject first revisions targeting archived plots (while still allowing edits to existing visits), or accept and let tablet/review handle it? Site-catalog only excludes archived plots from the default picker, so this is a real cross-segment gap.
