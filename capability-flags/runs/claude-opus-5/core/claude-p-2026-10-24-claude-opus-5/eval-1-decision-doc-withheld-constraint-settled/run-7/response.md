Phase 2 complete. `docs/intent/registry/registry-design.md` is now written around the local SQLite index, and I removed a now-stale sentence from the HLD ("Its private lookup backend remains open." → "Its lookup backend is private to the node.").

**What the design now says:** each snapshot owns a directory holding a built `index.db` plus its manifest; a single `active` pointer file names the live one. The index is two tables — `equipment` keyed by the normalized serial under `BINARY` collation, and a one-row `snapshot_meta` so a lookup reads the snapshot date from the same file as the record. Import verifies the signature, rejects unsupported schema versions, builds the index streaming the NDJSON (duplicate serials surface as primary-key conflicts, so no second pass), then activates by rewriting the pointer — any earlier failure leaves the previous snapshot active. One previous generation is retained so a bad-but-valid snapshot can be backed out by a pointer rewrite rather than a USB trip. Six Decisions & Alternatives rows carry the rejected options and why.

**One thing I should flag about the choice itself.** You said the three looked close. Against the HLD they aren't: the first tenet is "All serial-number lookup SHALL complete using files on the kiosk; no runtime network access is permitted," and the second says kiosks have no network route during normal operation. The on-site HTTPS directory and the managed search service both put a network call on the lookup path, so each would have required taking a tenet down, not just accepting a tradeoff — the sketch presented them as peers and shouldn't have. That's also why I recorded this as a Decisions row rather than offering a decision doc: an inherited constraint eliminated the alternatives, so a cold reader needs one line, not re-litigation. If you read those tenets as softer than they're written — e.g. a lab-network lookup was always on the table — say so, because that's an HLD-level correction and would reopen the option set rather than just this row.

**Edge-case probe** (delegated to a blind reader given only the arrow artifacts). Ten gaps came back; these are the ones I'd fix in the LLD now:

1. **No cold-start or broken-pointer state.** What does `findBySerial` return when `active` is missing (fresh kiosk), empty, or names a directory whose `index.db` is unreadable? Both result types require a snapshot date, so there's either a third outcome or an undefined date.
2. **The atomicity claim doesn't name its mechanism.** "A single small file write followed by a flush" could be truncate-and-rewrite in place (not atomic — power loss can leave a partial pointer) or write-temp-then-rename (atomic). I asserted the reader-safety property without saying which.
3. **Pruning is unordered relative to activation.** If pruning runs before the pointer write and activation then fails, there may be no generation left to roll back to.
4. **The manifest copy has no step.** The layout requires `manifest.json`; steps 1–5 never write it.
5. **Is the pointer re-read per lookup or cached?** Cached means lookups after an activation keep serving the old snapshot and its date, against REG-004; re-reading per lookup is a cost unaccounted in the 250 ms budget.
6. **Malformed records are unspecified.** Unparseable NDJSON line, missing `description`/`due_date`, non-ISO or nonsensical dates — skip-and-report, reject the import, or insert as-is.
7. **Normalizer domain edges.** Whether whitespace means ASCII or Unicode, whether internal whitespace survives, whether non-ASCII letters fold, what an empty-normalizing serial does. Since build/query normalizer identity is an invariant, these decide record reachability with no error surfacing.

And four I'd lean toward deferring as open questions, since they're operational rather than lookup-correctness: duplicate detection's error shape (which serial, which offset), rollback's effect on retention and re-importing the same snapshot, a one-row constraint and record-count cross-check on `snapshot_meta`, and import/lookup concurrency locking. #7 arguably belongs with the fix set if you expect non-ASCII in serials.
