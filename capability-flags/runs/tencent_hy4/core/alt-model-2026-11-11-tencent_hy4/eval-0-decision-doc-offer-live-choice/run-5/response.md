> **Approach** — Keep one authoritative board per event. Editors submit commands over HTTPS; the server assigns each committed edit one event revision. Browsers hold a revisioned view of the board and stay current over a self-hosted WebSocket connection. The delivery service manages each browser's session and publishes committed revisions as they occur; the change store keeps a replayable revision history. When a browser reconnects after a gap, it catches up from the last revision it holds. Three components divide this responsibility: the change store exposes replayable revisions and reliable publication; delivery owns session lifecycle and fan-out; browser sync owns the subscription, reconnect, and catch-up logic.
>
