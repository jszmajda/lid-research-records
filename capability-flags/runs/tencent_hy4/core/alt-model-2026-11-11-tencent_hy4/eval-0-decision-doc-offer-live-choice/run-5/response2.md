The tenet *Self-hosted and managed infrastructure are both permitted* + non-sensitive data means a managed service is not excluded by any inherited constraint, so the choice is a genuine trade, load-bearing for the change store, delivery, and browser sync.
>
> **Decision Elements** — Goals are standing constraints all options pass, so no gate is in play (background, not decision elements). Graded criteria: **Vendor independence — major**; **Connection and reconnect operations — major**; **Failure visibility — moderate** (importance derives from the tenet *Connectivity failures must be visible, not mistaken for an unchanged board*); **Update latency beyond the floor — moderate**.
>
> **Options in the Domain** — *Five-second HTTPS polling* (cursor reads; stateless; Verdicts: Vendor ind. Strong / Ops Strong / Visibility Partial / Latency Weak). *Self-hosted WebSockets* (persistent sessions, replayable revisions, reconnect/catch-up; Verdicts: Vendor ind. Strong / Ops Weak / Visibility Strong / Latency Strong). *Hosted realtime service* (provider SDK, publication reconciliation, recurring fees; Verdicts: Vendor ind. Weak / Ops Strong / Visibility Strong / Latency Strong). Each with a strongest-honest description, a concrete demonstration, clinical verdict+fact analysis, and a neutral one-line summary.
>
> **Selection** — *Self-hosted WebSockets*: the only option strong on both major criteria while delivering without a polling interval. Polling is partial on failure visibility (a stale board can read as unchanged, against the tenet); hosted matches on latency/visibility but is weak on the major vendor-independence criterion. Turns on *Connectivity failures must be visible…*; names *Self-hosted and managed infrastructure are both permitted* because it keeps the hosted option in contention. Vendor independence is a preference, not a standing constraint, so it's weighed, not a gate. Forecloses stateless/managed delivery; obligates the change store (replayable ordered revisions + reliable publication), delivery (sessions, capacity, publication), browser sync (subscription, reconnect, catch-up), and operating capacity within 99.5% availability. The weak ops criterion is the cost taken on in exchange.
