**Concern: view-tab cell rewrite on republish (sheets-view)**

- [Ubiquitous] A view tab's data range is fixed at `'{tab}'!A{DATA_START_ROW}:Z`, with `DATA_START_ROW = 2` (row 1 reserved for the header).
- [Event-driven] WHEN a tab is republished, the system SHALL write `tab.rows` (each cell's `Cell::Value`/`Cell::Formula` text) as ONE atomic `update_range` call over the data range — a wholesale replace, never an append.
- [Event-driven] Republishing with fewer rows than previously published SHALL truncate the residual tail to the exact new row count (no leftover stale rows, no half-written window).
- [Ubiquitous] The frozen header (row 1) SHALL be written exactly once, at first bootstrap, and SHALL NEVER be rewritten by a later republish; every subsequent republish MUST present a byte-identical header (enforced: `assert_eq!` fires — treated as a hard contract violation — if a later header differs).
- [Event-driven] WHEN `update_range` on the data range fails with a missing-tab error, the adapter SHALL: (1) `ensure_sheet` to create the tab, (2) write `tab.header` once to `'{tab}'!A1`, (3) then write the data range — in that order, on a fresh workbook this is not an error.
- [Unwanted behavior] IF any write step (data update, or any step of the create/header/data bootstrap sequence) fails, THEN the call SHALL return `Err(ViewError::PublishFailed)` and the tab's previously-published content SHALL be left untouched (no partial write lands).
- [State-driven] WHILE republishing multiple tabs, each tab is handled independently: success clears that tab's stale flag; failure adds the tab to the stale set and best-effort writes an in-tab banner `"STALE — last sync {ts}"` to cell `AA1`; a banner-write failure is swallowed (not surfaced), and the stale flag still stands (TUI is the fallback staleness surface).
- [Event-driven] After per-tab writes, the system SHALL reassert the fixed workbook tab order (`set_tab_order`); its failure marks the overall outcome `published: false` but does not itself alter per-tab stale flags.
- [Ubiquitous] The advisory write-lock SHALL be acquired before any tab mutation and released after. [Unwanted behavior] IF the lock is held elsewhere, THEN republish SHALL write to NO tab, return `published: false`, and leave the stale set unchanged (non-destructive refusal, no concurrent write).
- [Event-driven] The settle-pass price read-back (`read_price_pass`) SHALL run only strictly after every write in the same republish cycle has completed — never inline with or before a formula write.
- [Ubiquitous] Positions read-back parses column 4 (`Price`) and column 12 (`Quote Date`, integer days-since-1970): empty / `"Loading..."` (case-insensitive) / `"#N/A"` → Transient; any other `"#"`-prefixed cell → Permanent; f64-parseable → Numeric (quote date defaults to `Date(0)` if column 12 unparseable); otherwise → Permanent.
